# bitejson — 位并行 JSON 日志读取算子

矿井提升机 / 索道钢丝绳检测的现场设备每次检测会吐出几千万行 JSON 日志，一行一个事件，
字段嵌套数层。分析引擎只用到其中三四个字段，但标准库必须把整行解析成通用树才能取值。
本包实现一个只解码所需字段的读取算子：先用位运算一次性给整块输入建出结构索引，再按
查询路径只把命中的值解码成列。

## 设计要点（对应需求）

1. **结构字符位图，不逐字符判断。** 每个 8 字节字用 SWAR 比较一次算出引号、反斜杠、
   花括号、方括号、冒号、逗号各自的高位掩码，`movemask` 压缩成 8 位，八个字拼成 64
   字节一组的位图（`swar.go`, `classify.go`, `scanner.go`）。

2. **转义奇偶用位运算。** 连续反斜杠的奇偶由一次并行加法算出：奇数长度结尾是未转义
   的反斜杠、后面的字节被转义，偶数长度整段都被转义；跨字、跨块用进位接上
   （`resolveEscapes`）。

3. **前缀异或算字符串内部。** 对去掉转义引号后的引号位图做 5 次移位异或得到前缀奇偶，
   左移一位即"本字节之前已进入字符串"，字符串内部的结构字符随即从位图里去掉
   （`resolveStrings`）。换行符永远在字符串外，遇到即重置进位，因此一行坏掉不会吞掉
   后面的行。

4. **第二遍只沿结构字符走。** 逐行解析器用位图跳过空白的整段和字符串主体，只在结构
   位置上回溯，产出 token 流；路径被编译成 trie，**一趟扫描**同时匹配所有列，不需要
   的子树用一次跳步整体跳过（`matcher.go`, `extract.go`）。

5. **按路径解码。** 支持点路径、数组下标 `arr[3]`、通配 `arr[*]` 和带引号的键
   `"a\"b"`；数字自动识别为整数或浮点，超出 float64 范围报错并给出位置（`path.go`,
   `decode.go`）。

6. **全程校验 UTF-8。** 非法字节序列、截断的多字节字符、写错的 `\u` 代理对都报出具体
   位置。UTF-8 校验由 `StrictUTF8` 开启；代理对校验由 `StrictEscapes` 开启（默认行为
   与 `encoding/json` 一致，把孤立代理解码成 U+FFFD）。

7. **单行失败不连累其他行。** 一行解析失败只把该行标坏、记录位置，继续处理后续行；
   行边界取不在字符串内的换行符。

8. **类型统一。** 同名列在不同行类型不同时按规则处理：null/缺失填空、单一类型直接采用、
   整数/浮点拆成整型或浮点列，标量混合在 `UnifyColumnTypes` 下统一为文本，容器与标量
   混合则报类型冲突（`Table.Finalize`）。

## 命令行验证

```
go run ./cmd/verify -lines 20000            # 生成语料，全量对比 + 块不变性 + 吞吐
go run ./cmd/verify -lines 500000 -page page.html   # 另写一份可视化页面
```

`cmd/verify` 随机生成带深层嵌套、长字符串、大量转义、各种 Unicode 和故意弄坏的行的
语料，然后：

- **逐格对比**：每行用 `encoding/json` 完整解析后按路径取值，和本引擎抽出的列逐格比较，
  失败的行的**出错位置**也与标准库逐一比对；
- **块不变性**：按 1、7、8、13、63、64、65、4093 字节等块大小重新切块，结果必须完全
  一致；另有随机切点测试；
- **吞吐对比**：位并行引擎 vs 逐字符解析（`encoding/json` 逐行完整解码）。

## 可视化页面

`-page` 输出一个自包含 HTML，分四块：

1. 输入块结构字符位图：每 64 字节一组，逐类位图 + 字节着色（橙=引号、红=转义、
   蓝=字符串内）；
2. 每行抽出的列：每条路径一列，缺失显示为 `—`，坏行标红并给出错误位置；
3. 各阶段耗时：建结构位图 / 行切分 / 解析抽列；
4. 速度对比：结构位图（位运算 vs 逐字节）与整条流水线（位并行 vs `encoding/json`）
   的吞吐和加速比。
